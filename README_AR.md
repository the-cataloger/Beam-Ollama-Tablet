# Beam Space — تطبيق Android WebView للتابلت

**الحالة:** مشروع أندرويد قابل للبناء (Android/Java/WebView)، إصدار 1.0.0. لا يحتوي هذا الملف المضغوط على APK مُجمّع؛ يحتاج إنشاء APK إلى بيئة Android SDK أو GitHub Actions. لم نختبر اتصال Ollama فعليًا، إذ يتطلب مفتاح API يملكه المستخدم.

## المميزات

- واجهة حديثة بالعربية، مناسبة للتابلت أفقيًا أو رأسيًا.
- نموذج ثابت: **Beam** عبر **Ollama Cloud** (المعرّف المباشر `beam`).
- استجابات تدريجية Streaming، وإمكانية إيقاف التوليد.
- سجل المحادثات محلي داخل WebView؛ إنشاء محادثة، حذف، نسخ، وتصدير TXT.
- حقل لتعليمات النظام ودرجة Temperature.
- حفظ مفتاح Ollama API **مشفّرًا** باستخدام Android Keystore (AES-256-GCM)، مع عدم إظهاره في HTML/JavaScript/localStorage.
- طلبات الشبكة تُنفّذ في Java أصلية عبر HTTPS فقط؛ لا تحتاج إلى تنزيل Ollama أو Beam على التابلت.
- بدون خادم وسيط، وبدون أذونات غير الإنترنت، وبدون مكتبات خارجية وقت التشغيل.

## الحصول على API Key

1. افتح https://ollama.com/settings/keys وسجّل الدخول.
2. أنشئ مفتاح API جديدًا (**لا تشاركه مع أحد**).
3. افتح التطبيق ثم **الاتصال والإعدادات** وأدخل المفتاح واحفظه.
4. ابدأ محادثة؛ عند أول استجابة ستتأكد عمليًا من صلاحية الاتصال.

**مهم:** إتاحة Beam مجانًا معلنة **لفترة محدودة** فقط وفق https://ollama.com/blog/reflection-beam ؛ قد يتغير السعر أو يتطلب الحساب رصيدًا لاحقًا. التطبيق لا يتجاوز قيود الخدمة.

## بناء APK على GitHub Actions — بدون Android Studio

1. أنشئ مستودعًا **خاصًا** على GitHub.
2. ارفع **محتويات** هذا المجلد (بما فيها مجلد `.github` المخفي) إلى جذر المستودع، على الفرع `main`.
3. افتح تبويب **Actions** ثم اختر **Build Android APK**. يبدأ البناء عند رفع الملفات، أو اختر **Run workflow**.
4. بعد نجاح البناء، افتح تشغيل المهمة وانزل إلى **Artifacts**؛ نزّل `BeamTablet-debug-apk`.
5. فك ZIP الناتج وستجد `app-debug.apk`؛ انقله للتابلت وثبّته بعد تمكين تثبيت التطبيقات من هذا المصدر.

**التوقيع:** ملف `app-debug.apk` موقَّع بمفتاح تطوير آلي صالح للاختبار الشخصي، وليس إصدار إنتاجي للنشر على متجر التطبيقات. التحديثات عبر أجهزة مختلفة قد تتطلب إعادة تثبيت إن اختلف مفتاح التوقيع، مما يمسح بيانات التطبيق القديمة.

## البناء محليًا عند توفر Android SDK

- يتطلب JDK 17 وAndroid SDK Platform 35 وAndroid Build Tools 35.0.0 وGradle 8.9.
- من جذر المشروع نفّذ:

```bash
gradle :app:assembleDebug
```

- الناتج: `app/build/outputs/apk/debug/app-debug.apk`.

## الخصوصية والقيود

- لا تضع مفتاح API داخل كود الواجهة؛ يُمرَّر عبر جسر Native ويُخزَّن مشفرًا.
- تُخزَّن المحادثات في localStorage العادي في مساحة التطبيق؛ ليست مُشفرة بواسطة Keystore. لا تُخزِّن بها أسرارًا مؤسسية بالغة الحساسية.
- تُرسَل نصوص الرسائل وتعليمات النظام إلى Ollama Cloud للمعالجة، ولا تعمل الخدمة بدون اتصال بالإنترنت.
- Beam **نص إلى نص**، فلا يدعم في هذه النسخة رفع الصور/قراءة PDF مباشرة. يمكن إدراج نص رقمي من فهرس، لكن لا يوجد OCR مدمج.
- لا توجد أدوات برمجية للوكيل: إمكان استخدام tools لدى النموذج لا يعني أن التطبيق ينفذ SQL أو يصل إلى الملفات.
- يتم إرسال آخر 28 رسالة نصية بحد أقصى 130 ألف حرف من المحادثة، لتقليل التكلفة ومنع التضخم. لا تساوي هذه الحدود طول سياق النموذج الأقصى.
- زر الحالة يعني **مفتاح محفوظ**، لا يعني نجاح اختبار الاتصال أو أن الخدمة متاحة الآن.
- الاتصال السحابي لم يُختبَر بمفتاح حقيقي أثناء إعداد الحزمة؛ لا يُدَّعى أن التطبيق اختُبر على جهاز Android فعلي.

## تنبيه أمني

بما أن مصدر الصفحة محصور في `appassets.androidplatform.net` ويُقدَّم من أصول محلية ثابتة، فقد منعنا تحميل صفحات خارجية داخل WebView. فتح الروابط الخارجية يُحوَّل إلى تطبيق المتصفح؛ ولا يُسلَّم مفتاح API لصفحة ويب خارجية. طلب API الوحيد في Java يستهدف HTTPS على `ollama.com`.
